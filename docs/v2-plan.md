## 2. 首版范围与交付目标

首版聚焦两个用户结果：在 Bigme HiBreak S Color 上能读清、点准、正常输入；手机使用结束后，电脑终端能按原有策略恢复尺寸。

| 需求 | 首版应达到的效果 | 范围判断 |
| --- | --- | --- |
| 墨水屏阅读 | 终端、菜单和说明文字无需浏览器临时放大即可阅读 | 核心功能 |
| 触摸操作 | 主要按钮易点，键盘展开后仍能操作终端 | 核心功能 |
| 手机切回电脑 | 释放控制后，tmux 按原策略恢复尺寸 | 核心功能，技术风险最高 |
| 性能 | 长输出、输入、滚动和重连不出现明显退步 | 首版必须验收，进一步优化依测量决定 |
| 手动部署 | 保留身份、可验证版本、可回滚 | 首版交付条件 |
| 自有 Release / OTA | 从自己的仓库可靠升级 | 后续独立阶段 |

目标设备和浏览器沿用需求文档：Bigme HiBreak S Color、Brave Nightly。字号、尺寸和宽限时间均应通过该设备实测确定，不将建议起点视为验收结果。

## 3. 需求文档需要补充的关键问题

### 3.1 开发实例必须完整隔离

仅更换端口、密钥目录和测试会话名称，不能保证开发实例与正式实例互不影响。

源码中存在以下行为：

- `TerminalService` 构造时执行 `clearStalePipes()`，扫描同一 tmux 服务的会话，并对发现的输出管道执行关闭操作。
- `PaneChannel` 的目录优先级是显式注入、`POCKETSHELL_RUN_DIR`、`~/.pocketshell/run`；默认路径不随 `POCKETSHELL_KEY_DIR` 改变。
- 接管会话时会设置 tmux 的全局 `status off`。

据此判断，照原文档启动第二个 Agent，即使只准备使用专用测试会话，也可能干扰正式实例的输出管道或 tmux 配置。

开发环境应同时隔离：

| 对象 | 隔离要求 |
| --- | --- |
| 网络入口 | 独立监听端口；真机使用独立 HTTPS 测试域名 |
| 身份与配置 | 独立 `POCKETSHELL_KEY_DIR` |
| 通道文件 | 独立 `POCKETSHELL_RUN_DIR` |
| tmux 服务 | 独立 socket / 服务实例，覆盖全部 tmux 调用 |
| 会话和数据 | 使用专用测试会话及测试内容 |

更稳妥的方式是使用独立系统用户或容器。若同一用户运行多个实例，必须核验所有同步、异步 tmux 调用均指向开发服务，不能仅在手动创建测试会话时指定独立 socket。

tmux 的 `-L`、`-S` 和 socket 目录机制可用于隔离服务，但项目的具体接入方式仍需在实施时确认。完成隔离前，不启动第二个 Agent 连接生产 tmux 服务。

源码参考：[启动清理及会话管理](../agent/src/terminal.ts)、[通道及运行目录](../agent/src/pane-channel.ts)。机制参考：[tmux 官方手册](https://man.openbsd.org/tmux.1)。

### 3.2 尺寸修改分散在多个入口

当前普通 resize、打开或重建通道，以及刷新终端都会调用 `resize-window`。普通 resize 路径还存在通道层与服务层重复调用。

因此，只在断线回调中恢复一次窗口策略并不足够：之后的刷新、重连或通道重建仍可能将窗口重新设为手动尺寸。后续应统一管理所有改变窗口尺寸的入口。

源码参考：[TerminalService](../agent/src/terminal.ts)、[PaneChannel](../agent/src/pane-channel.ts)、[服务端消息处理](../agent/src/server.ts)。

### 3.3 大字号与尺寸保护需要联合设计

前后端目前都要求至少 20 列、4 行。字号扩大到 24、工具栏增高及软键盘展开都会压缩可用终端空间，必须联合验证。

这些保护用于防止异常测量导致终端输出按错误尺寸排版，不能为了支持大字号直接降低阈值。真实窄屏若触及限制，应明确界面反馈和布局处理，避免用户看到字号变化却不知道远端尺寸未更新。

源码参考：[前端 fit 保护](../app/src/lib/term/fit-guard.ts)、[后端尺寸校验](../agent/src/sane-size.ts)。

### 3.4 底部导航应单独纳入改造

实际底部导航位于 `BottomBar.svelte`，包含较小的固定字号和固定高度。只修改设置页、虚拟键盘、状态栏和标签栏，不能完整解决底部阅读问题。

源码参考：[BottomBar](../app/src/components/BottomBar.svelte)。

## 4. 墨水屏适配方案

### 4.1 设置模型与默认行为

采用“本地模式 + 独立字号 + 高对比主题”。现有偏好已保存在浏览器本地，可以直接扩展，无需为本次需求增加服务端偏好同步。

“按设备保存”在这里具体指按浏览器配置和站点存储保存。不同浏览器、配置文件或入口是否共享存储需要验证，不应承诺同一物理设备上的所有入口自动同步。

| 设置 | 建议行为 |
| --- | --- |
| 墨水屏模式 | 手动开启，首次使用保持现有体验 |
| 界面字号 | 独立于终端字号，提供少量易理解的档位 |
| 终端字号 | 保留原设置，试验性扩展至 24；18 作为真机比较起点 |
| 墨水屏主题 | 白底、深色文字、明显边框，保留必要的颜色语义 |
| 动效 | 停止装饰动画和光标闪烁，使用静态状态提示 |
| 关闭模式 | 恢复原主题和普通显示偏好，避免要求用户重新配置 |

新增设置应有明确默认值、取值校验和旧数据兼容行为；不能仅扩大设置面板滑块范围。界面字号的各档位与终端字号继续相互独立。

### 4.2 字号与触摸布局

建立统一的文字、间距和触摸尺寸变量，再逐项替换核心组件中的固定值。不要仅修改 `body` 字号，也不要使用全局强制字号或整体缩放替代布局适配。

建议起点：

- 正文和主要操作文字为 16px，辅助文字为 14px，分组标题可从 18px 开始，再随字号档位调整。
- 普通主要按钮目标至少 44×44 CSS 像素；虚拟键盘单独处理窄屏布局，不机械地给每个键设置同样宽度。
- 字号变大后允许说明换行、设置行堆叠，检查固定高度与溢出，避免文字和控件被裁切。
- 优先复用已有 `layered` 键盘布局进行真机比较，首版无需重新设计整套虚拟键盘。

第一轮覆盖设置页、底部导航、状态栏、标签栏、虚拟键盘和常用菜单。文件、Git 等面板至少完成可读性巡检，避免进入次级页面后重新出现难读文字。

### 4.3 配色与动效

现有主题从 `.ghostty` 配色派生整套界面颜色。新增白底主题后，需要检查实际派生结果，必要时为墨水屏模式覆盖灰字、阴影、透明效果和边框样式。

新增主题还需同步核对类型与白名单、主题生成流程、界面选项和中英文文案，不手改生成的主题 CSS 作为长期方案。

成功、警告、错误及选中状态应能通过文字、图标或边框区分，不能只依赖颜色。停止装饰动画和光标闪烁时，仍需保留清晰的加载和连接状态反馈。

终端程序直接输出的 RGB 背景色可能不受调色板控制。首版应针对常用工具验证其自身浅色或高对比配置，暂不在终端字节流中强制去色，以免破坏反色、选择和全屏程序显示。

## 5. tmux 尺寸控制生命周期方案

### 5.1 集中管理尺寸控制权

建议引入服务端尺寸控制模块，统一处理接管、调整、释放和超时恢复。所有改变窗口尺寸的路径，包括普通 resize、通道初始化或重建、终端刷新，都经过该模块。

用户交互保持简单：当前设备控制尺寸时可点击“释放尺寸控制”；需要时通过“接管尺寸”重新取得控制。

尺寸控制只决定哪个客户端可以改变窗口尺寸，不应顺带改变输入权限。输出订阅、输入权限和尺寸控制是不同概念。

### 5.2 场景规则

| 场景 | 建议行为 |
| --- | --- |
| 无控制者，用户进入会话 | 可自动取得尺寸控制 |
| 已有其他网页控制者 | 展示控制状态，通过明确操作接管 |
| 主动释放 | 立即恢复原策略，后续普通 resize 不自动重新接管 |
| 短暂断网 | 在宽限时间内保留控制，同一客户端可恢复 |
| 后台挂起或断线超时 | 服务端判定过期并恢复，不仅依赖页面关闭事件 |
| 切换标签页 | 原窗口进入释放宽限期，避免快速切换导致频繁变化 |
| Agent 正常退出 | 尽力恢复仍由自己控制的窗口 |
| Agent 异常退出或重启 | 根据持久记录核验并恢复遗留控制 |
| 窗口已关闭 | 清理对应记录，不对其他窗口执行恢复 |

宽限时间与续期方式需要结合移动浏览器后台行为验证。主动释放后应保持释放状态，不能因视口变化、重新聚焦或普通重连而无提示接管。

### 5.3 状态保存与恢复

按真实窗口管理控制状态，至少关联 tmux 服务身份和窗口 ID，不能只依赖可能改名的会话名称。

首次改变尺寸前保存：

- 窗口是否继承全局 `window-size`。
- 窗口原有的显式尺寸策略。
- 原来处于 `manual` 时的窗口尺寸。
- 当前控制者、控制代次和恢复所需的目标身份信息。

恢复规则：

- 原来继承全局配置：删除本次产生的窗口级覆盖，重新继承。
- 原来显式指定策略：恢复该策略。
- 原来显式使用手动尺寸：恢复策略及对应尺寸。
- 恢复前检查目标仍是原窗口，并核验是否有外部改动，避免用过期记录覆盖用户后续配置。

不能统一设置为 `latest`。根据 [tmux 官方手册](https://man.openbsd.org/tmux.1)，`resize-window` 会自动将窗口级 `window-size` 改为 `manual`，恢复原策略必须成为控制生命周期的一部分。

如果验收要求覆盖异常退出，控制记录必须在首次 resize 前可靠保存，并在启动时检查与恢复；仅保存在 Agent 内存中无法满足这一要求。

### 5.4 并发、订阅和显示一致性

服务端应拒绝旧控制者和过期控制代次的请求。接管或释放后，迟到的 resize、重连回调及刷新操作不能重新夺回控制。

当前 `detach` 仅取消输出订阅，且前端已有标签切换宽限逻辑，不能直接将它等同于永久释放尺寸。需要协调两者生命周期，并验证短暂切换与长期离开的区别。

非控制端还需依据实际窗口尺寸显示，通过滚动等方式适配较小视口。不能只拒绝其 resize，却仍假设远端终端完全匹配该端本地尺寸；普通输出和全屏程序都需要验证。

网页客户端的唯一控制者不等于 tmux 原生客户端被禁止操作。手机释放后，应由恢复后的 tmux 策略处理电脑终端尺寸；不自动断开电脑终端。

### 5.5 旧状态的迁移边界

已经被旧版本留在 `manual` 的窗口，无法仅凭当前状态判断它原来是否由用户主动设置。

新版本应提供明确的一次性恢复入口，让用户选择恢复为继承策略等行为，不猜测并批量覆盖。首次部署前应记录受影响窗口，区分历史遗留状态与新版本实际恢复结果。

## 6. 性能优化原则

先在同一设备、同一输出内容和相同显示条件下建立对照，再决定是否修改渲染或批处理。

主要记录：输入延迟、首次可读时间、重连恢复时间、长输出顺序与完整性、滚动体验及空闲重绘情况。具体性能阈值应在基线测量后确定，不将尚未测量的数值写成承诺。

首版优先减少装饰动画、光标闪烁和无意义重绘。保留已有 WebGL、流控、重放、尺寸保护和 xterm 补丁，依据实测再调整。框架、Bun 和 xterm.js 升级与本次业务修改分开进行。

墨水屏刷新模式、残影和浏览器渲染都影响最终观感，必须依赖真机对照。不能仅凭桌面截图或自动化测试通过，认定墨水屏体验已经合格。

## 7. 分阶段实施与交付

| 阶段 | 主要工作 | 进入下一阶段的条件 |
| --- | --- | --- |
| A：开发基线 | 完整隔离开发环境，记录版本、设备视口和原显示效果 | 开发实例不影响正式终端 |
| B：墨水屏界面 | 模式、字号、主题、触摸布局及动效控制 | Bigme 真机阅读和输入可用 |
| C：尺寸生命周期 | 统一尺寸入口、接管释放、超时恢复及重启恢复 | 手机与电脑切换、多连接场景通过 |
| D：首版交付 | 完整回归、嵌入式构建、版本及缓存核验、回滚演练 | 浏览器与 PWA 均更新且保留身份 |
| E：后续维护 | 性能专项、自有 Release、OTA 信任来源及升级测试 | 测试实例升级及失败恢复通过 |

B、C 应分别形成可审查的改动；正式首版同时具备两项能力。实际执行时通过 Beads 拆分任务及依赖，本文不记录开发完成状态。

| 布局 | 大字号、竖横屏、窄视口、软键盘展开与收起 | 控件不裁切、菜单可滚动、输入区域可见 |

| 设置 | 刷新、重开、切换模式、不同浏览器配置 | 偏好按预期保存，关闭模式可恢复原显示设置 |
| 尺寸策略 | 继承策略、显式策略、原有手动尺寸 | 释放后恢复对应策略及必要尺寸 |
| 连接生命周期 | 主动释放、断网、后台恢复、双设备及多标签页 | 无反复争抢，无过期请求重新接管 |
| 目标生命周期 | 会话改名、窗口删除、Agent 正常或异常重启 | 不误恢复其他窗口，遗留状态按设计处理 |
| 稳定性 | 长输出、历史滚动、全屏程序重绘 | 输出顺序及完整性正常，显示不明显退步 |
| 交付 | 前后端版本、普通标签页、PWA、原设备身份 | 获取新资源，版本一致，原设备仍能连接 |
| 回滚 | 测试实例替换为备份二进制 | 能恢复服务与连接，不依赖清空站点数据 |

尺寸恢复以新输出、程序重绘和电脑终端后续缩放为判断依据；已有输出中的硬换行不一定能因恢复尺寸而消失。

## 9. 构建、部署与后续发布

### 9.1 首版手动部署

生产交付是嵌入前端资源的 Agent 单文件二进制，修改 Svelte 或 CSS 后仍需重新构建 Agent。

正式构建与部署前，应确认生产服务实际路径、用户、版本及数据目录，完成备份并安排维护窗口。保留原域名和配对身份，在数据兼容前提下避免重新配对。

当前前后端版本和缓存标识包含 Git SHA，正式产物应来自明确、已提交的源码状态，避免在同一提交上反复构建未提交修改造成版本与缓存难以区分。提交、发布及生产部署在实际执行阶段按授权进行，本文不执行这些操作。

首版继续关闭 OTA，防止定制版本被上游更新覆盖。部署后同时验证普通浏览器与 PWA 获取新资源，不以清空全部站点数据作为默认刷新方法。

回滚先验证备份二进制恢复流程。纯界面修改通常无需恢复数据目录；若后续引入不兼容的数据迁移，应单独设计数据回滚，避免直接覆盖升级后的新数据。

### 9.2 自有 Release 与 OTA

后续独立完善以下机制：

- 固定经验证的 Bun 版本，开发与 CI 保持一致。
- 调整发布顺序：修改版本、提交、检查与构建、核验产物、打标签、发布资产及校验和。
- 同步前后端版本，明确指定 fork 仓库，保持资产命名与更新器兼容。
- 保留许可证及第三方资源说明。
- 采用与现有解析逻辑兼容的递增三段数字版本；若需要 fork 后缀，先修改并测试相关解析逻辑。
- 将内置可信更新来源明确设为自己的仓库，保留来源校验。
- 验证更新目录权限、原子替换、服务重启及升级失败恢复。

设置 `POCKETSHELL_UPDATE_REPO` 只能改变检查来源，不能单独允许任意仓库更新。实施后的 `OFFICIAL_UPDATE_REPO` 是 `longcrawfish/Big-Pony-pocketshell`；应用更新同时核对仓库名与 `official`，保留可信来源边界。OTA 默认关闭，只有显式 `POCKETSHELL_UPDATE=1` 才启用。

发布脚本的正式运行包含提交、打标签、推送及创建 Release；`--dry-run` 只接受当前包版本，运行检查、构建和打包，不修改版本、提交、标签或远端。脏开发包带内容哈希，不能将其视为已完成版本升级的正式包。

## 11. 实施说明与复现方法（2026-10-17）

本节记录实现契约和验证方法。任务状态以 Beads 为准，Bigme 真机、生产部署和公开发布仍须各自满足验收条件。

### 11.1 开发隔离与工具链

使用 `.bun-version` 固定的 Bun 1.3.14，两项目分别执行 `bun install --frozen-lockfile`。Linux 测试依赖 tmux、libarchive-tools（bsdtar）；前端字体测试另需 uv 与 fontTools/brotli。CI 同样安装这些依赖。没有这些依赖时的失败或跳过不计为通过。

```bash
# 仓库根目录；终端退出用 Ctrl-C，正常恢复尺寸但保留开发会话。
bash scripts/dev-agent.sh eink
# 第二实例必须另用端口。
POCKETSHELL_PORT=18723 bash scripts/dev-agent.sh desktop
# 仅检查/结束明确命名的开发 tmux，不能省略 -S。
tmux -S "$PWD/.dev/eink/tmux.sock" list-sessions
tmux -S "$PWD/.dev/eink/tmux.sock" kill-server
```

开发脚本固定监听 127.0.0.1，分别使用 `.dev/<实例>/keys`、`run`、`tmux.sock`，关闭 OTA，清除继承的 TMUX/TMUX_PANE/PANE_TAP。所有业务 tmux 命令经同一 argv 构造器；指定 socket 时用 `-S <绝对路径> -f /dev/null`，不加载生产配置。未指定 socket 的现有安装保持原有默认 tmux 行为。测试预加载器创建独立临时目录并在退出时只终止自身 tmux。独立 e2e 与传输基准入口也指定自己的 socket、身份和运行目录。

启动清理是同步操作，在新通道打开之前完成。双可丢弃实例测试检查另一实例的 pipe-pane、窗口尺寸和配置在启动、通道重建及停止后保持一致；未用生产 tmux 做破坏性验证。故障排查先核对进程环境的 socket/key/run 三项，再只对该 socket 执行 `list-sessions`、`list-panes`。正常停止 Agent 不删除会话；只有丢弃整个开发实例时才运行上面的 `kill-server`。

### 11.2 显示偏好

新装仍使用原普通主题、10px 终端和 compact 界面。首次打开墨水屏模式使用 eink 主题、18px 终端、comfortable 界面和 layered 键盘，均为待真机验证的起始值。模式内手动调整会分别保存，退出恢复普通模式偏好；界面档位与终端字号相互独立。终端字号范围 10–24px；有效视口小于 20 列或 4 行时显示提示并保留有效远端尺寸。

eink 是白底深色 ANSI 主题，辅助文字、边框和状态文字加强对比，取消装饰动画、阴影和光标闪烁，选中/禁用另有轮廓或边框。应用输出中的显式 RGB 颜色不被改写，因此自行绘制深色/RGB 背景的 TUI 仍需其自身配置。选择、反色和中文阅读效果仍需 Bigme 真机确认。

### 11.3 尺寸控制契约

只有唯一网页控制者能改变窗口尺寸。订阅输出、发送输入、尺寸控制互相独立：观察端仍可输入和复制，按服务器实际网格显示，窄视口可水平/垂直滚动。原生 tmux 客户端不参加网页能力令牌协议；网页控制期间窗口为 manual，释放恢复策略后原生客户端可继续决定尺寸。

| 事件 | 服务端处理 | 客户端行为 |
| --- | --- | --- |
| 首次进入未控制的窗口 | 当前 revision 匹配且本设备未尝试时允许一次自动申请 | 先取得状态和有效测量；已主动释放的窗口不再自动申请 |
| 点击接管 | 快照/日志先落盘，创建新令牌与租约，旧令牌失效 | 使用当前 revision 显式申请 |
| resize / redraw | 核对已配对设备、连接、令牌、窗口身份和记录 | 只有控制者附令牌；观察端只记录本地可用视口 |
| 主动释放 | 立即撤销能力并恢复原策略 | 按 Agent 地址与窗口身份保存已释放标记；刷新/改名不清除 |
| 后台、切换会话、断线 | 最多保留 30 秒宽限 | 前台活动会话每 10 秒续期；离线不排队控制请求 |
| 宽限内重连 | 同一已认证设备与旧令牌可续期，新连接轮换令牌 | 旧连接迟到消息无效 |
| 租约超时 | 撤销能力，恢复策略；失败保留日志重试 | 接受状态通知；不重新自动申请 |
| 外部修改策略/尺寸/标记 | 放弃旧控制，不覆盖外部新状态 | 更新状态及网格 |
| 正常退出/重启 | 正常退出恢复；启动时先恢复残留记录 | 重新检查状态 |

默认租约 45 秒、宽限 30 秒、前台心跳 10 秒、状态检查 5 秒；这些是自动化测试参数，不是 Bigme 后台策略的已验收结论。

握手能力为 `size-control-v1`。RPC `term.size.status/acquire/release/renew/migrate` 均带 `session`；acquire 另带 `revision/force/cols/rows`，release/renew 带 `token`，migrate 带 `window/revision`。`sizeState` 返回窗口身份、revision、实际行列、原生策略、控制者 self/other/none，以及仅属于本连接的 token。旧客户端没有令牌的 tmux resize 被忽略；普通 shell 会话保留其既有 resize 语义。刷新终端不能从观察状态偷偷接管。

日志位于实例身份目录的 `size-control.json`，只存窗口身份、原策略/尺寸、随机所有权标记和预计尺寸，不保存密钥或终端内容。身份包含 socket 路径、inode/ctime、tmux pid/start_time 与 window ID，恢复不按会话名称匹配。首次修改前用临时文件写入、fsync、rename、目录 fsync；日志写入失败拒绝接管，损坏日志保留并禁用控制，不能自动猜测原策略。继承策略通过 unset 恢复，显式 latest/largest/smallest 原样恢复，原 manual（含继承全局 manual）同时恢复原尺寸。

窗口删除、服务器重建和外部修改均优先于恢复。Agent 能检测策略、尺寸或标记的实际变化；外部命令若恰好写入完全相同的状态，没有可观察差异，无法据此推断用户意图。历史 manual 的一次性恢复只在当前无控制者时显示，确认提示后重新核对窗口身份和 revision；不会扫描批量修改。旧输出已有硬换行不能逆转，以新输出和程序重绘验收。

### 11.4 验证环境与测量口径

开发起点为 `ccc2366`，本轮修改尚未提交。验证机为 Linux x86_64、Bun 1.3.14、tmux 3.5a；浏览器自动化为 Chromium 148.0.7778.96。初始检查发现依赖缺失（Bun/uv/bsdtar）及两个 Bun 压缩测试的 typed-array 类型错误；补齐依赖并修复类型后运行完整回归。前端原有依赖私有录制数据的 REPRO suites 继续跳过，其范围不算已覆盖。

```bash
(cd agent && bun run typecheck && bun test)
(cd app && bun run typecheck && bun run test && bun run build)
# Python 环境需 Playwright 及 Chromium；PS_BROWSER 可指定本地浏览器路径。
BUN_BINARY=bun python3 tests/browser/v2.py
# 两个均支持隔离 socket 的本地版本，使用同一测试身份/浏览器 profile 验证升级回滚。
PS_OLD_BINARY=/绝对路径/旧开发包 PS_NEW_BINARY=/绝对路径/新开发包 \
  BUN_BINARY=bun python3 tests/browser/artifact.py
```

浏览器脚本独立启动 Agent、tmux 与 Vite，覆盖 320/360/390px、横屏、普通模式恢复、双端接管、观察端网格滚动和中文输入、24px 下最小尺寸保护、主动释放跨刷新保持、关闭控制端后宽限恢复。输出目录默认 `/tmp/pocketshell-v2-browser`，保存报告和截图，不输出测试私钥。真实 tmux 测试另覆盖五种原策略、全局继承 manual、迟到能力、外部改动、改名/删除/ID 复用、日志写失败/损坏、实际 SIGKILL 后恢复，以及原生 tmux 客户端释放后的再次缩放。

首轮浏览器报告的首次取得控制为 888ms，仅是本机控制 RPC 的时间；不是首次可读时间或手机输入延迟，不能作为性能改善证据。Bigme HiBreak S Color + Brave Nightly 的实际视口、DPR、缩放、刷新模式、IME、PWA、细笔画和残影尚无测量值。

真机每次记录设备/浏览器版本、CSS 视口、DPR、网页缩放、屏幕刷新模式、界面档位、终端字体/字号、键盘和网络。性能比较在同设备、同内容、同显示条件下进行：

- 输入回显：至少 30 次固定短文本，用录屏逐帧记录按键到完整可读回显，报告 p50/p95 和输入法提交时间；不能以网络 RTT 替代。
- 首次可读：冷启动与已有缓存分开，各至少 10 次，从进入页面到固定首屏文字完整可读；记录连接与字体加载时间作诊断。
- 重连：固定编号输出中断网络后恢复，记录可读恢复时间，并核对编号顺序、重复/遗漏和滚动历史；前后台挂起另测。
- 长输出：使用固定 1000 行编号、中文、ANSI 色与反色文本，保存源文件 SHA256，对照 tmux capture-pane 与浏览器历史；分别验证普通屏和全屏/alternate buffer 应用。
- 空闲与滚动：静止 60 秒记录浏览器帧/终端重绘和屏幕刷新次数；固定距离滚动比较可读性与残影。后台恢复、旋转、IME 弹出/收回各重复 10 次。

没有这些真机前后数据时，不宣称 E1 的性能优化已完成，也不修改现有 WebGL、流控、重放及 xterm 补丁架构。

### 11.5 构建、发布和回滚边界

`build:bin` 默认拒绝脏源码。开发验证可设 `POCKETSHELL_ALLOW_DIRTY=1`，版本使用 `SHA-dirty-内容哈希`，同一个标识注入前后端与 Service Worker 缓存。`POCKETSHELL_BUILD_TARGETS=bun-linux-x64-baseline` 可缩短本地构建；正式发布脚本固定构建四个平台，避免环境变量导致误打包旧产物。构建成功或失败均恢复调用前的 embedded manifest。

```bash
# 仅生成开发验证包；版本必须等于当前两个 package.json 的版本。
bash scripts/release.sh 1.21.5 --dry-run
# 将来获准发布后，使用递增三段版本；该命令会提交、推送、公开发布。
# bash scripts/release.sh <新版本> --repo longcrawfish/Big-Pony-pocketshell
```

正式发布要求干净源码、origin 与内置信任仓库一致、固定 Bun 和 gh 登录。顺序为改版本→提交→冻结安装/类型检查/完整测试→构建→包内许可及 SHA256 核验→本机版本/SHA 核验→标签/推送→显式仓库 Release。平台包名和 `SHA256SUMS.txt` 与更新器匹配，包内包括 LICENSE、THIRD-PARTY-FONTS.md 和 THIRD-PARTY-THEMES.md。dry-run 不能替代已提交正式产物的验收。

更新器默认关闭；自定义环境仓库仅可检查，只有编译内置 fork 可执行。下载校验完成后先创建 `.prev` 备份，再原子替换；备份失败不替换，重启函数抛错时立即恢复旧文件。此回滚覆盖替换阶段和可同步报告的重启失败，不能保证操作系统已接受重启后新进程的健康；真实部署还须核验服务 Restart 策略、重启后健康检查及人工回滚。更新不迁移身份/配对目录，首版无需数据格式回滚。测试文件中的替换/失败恢复不能替代真实 Release 下载与生产升级验收。

更新检查缓存同时绑定当前二进制版本与仓库，升级/切换来源后旧缓存失效。若回滚到尚无此校验的旧二进制，停止服务后仅删除身份目录内派生的 `update-cache.json`，防止其显示新版本的陈旧检查结果；不要删除身份密钥、devices.json 或浏览器站点数据。隔离产物测试覆盖此旧版兼容步骤。

部署前须明确服务实际二进制路径/运行用户、监听地址、身份目录、socket、备份路径与维护窗口，记录权限私有的二进制及必要配置备份。部署后核对 `--version`、页面版本、HTTP/HTTPS、配对保持、PWA 普通刷新/关闭重开、双端尺寸释放与原任务连续性。失败时停服务、恢复备份二进制、保持身份目录原位，再按原服务定义启动并复核。当前没有修改生产服务、创建发布标签或启用生产 OTA。
